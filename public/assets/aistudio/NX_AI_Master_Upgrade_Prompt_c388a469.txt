======================================================================
1. CORE PRODUCT VISION
======================================================================

NX AI is NOT primarily a dashboard.

NX AI is a human-like Windows AI assistant with:

1. its own female 3D character,
2. natural voice conversation,
3. text chat,
4. memory,
5. reasoning / planning,
6. learning from useful user instructions,
7. autonomous Windows computer control,
8. multi-step and multi-task execution,
9. local-first operation,
10. optional cloud/API intelligence,
11. realtime activity/state awareness,
12. and a persistent desktop-companion presence.

The user should be able to talk to NX AI naturally.

Example:

User:
"Chrome kholo aur YouTube pe Pakistani drama ka trailer search karo."

NX AI should:
- hear the user,
- transcribe/understand the command,
- identify the language,
- reason about the task,
- plan the steps,
- execute the task on Windows,
- observe whether each step succeeded,
- recover if something unexpected occurs,
- answer naturally,
- and visually show the character listening/thinking/working/speaking.

The user should feel like:
"I am talking to an assistant that lives inside my computer and can actually use my computer."

The product should NOT feel like:
"A web dashboard with a list of predefined buttons."

14. LOW-LATENCY VOICE
======================================================================

Absolute physical zero milliseconds is impossible.

Therefore target:
"near-zero perceived latency."

Remove unnecessary waiting.

Possible principles:
- streaming audio input,
- voice activity detection,
- incremental speech recognition,
- streaming model responses,
- early response planning where safe,
- streaming TTS,
- audio buffering kept small,
- reuse persistent connections,
- warm model/session states,

15. BARGE-IN / INTERRUPTION
======================================================================

If NX AI is speaking and user starts speaking:

1. Detect user speech.
2. Stop/duck current TTS immediately.
3. Preserve conversational context.
4. Switch character to listening.
5. Process the interruption.

Example:

NX:
"Main aap ke liye file..."

User:
"Ruko."

NX immediately stops speaking.

Then:
"Jee, ruk gayi."

This must be tested in actual runtime.

======================================================================

- try safe recovery,
- retry where reasonable,

-> if still unavailable, report clearly.

-> pause task.
-> inform user.
-> reconnect detection.
-> resume only according to safe checkpoint.

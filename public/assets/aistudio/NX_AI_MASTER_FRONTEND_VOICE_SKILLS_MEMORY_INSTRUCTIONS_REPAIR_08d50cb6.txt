NX AI — MASTER INTERACTION, FRONTEND, VOICE, SKILLS, MEMORY, INSTRUCTIONS, API VALIDATION & AGENT QUALITY REPAIR PROMPT
====================================================================================================================

MISSION
=======

Take the CURRENT NX AI repository exactly as it exists and perform a complete forensic audit, repair, implementation, integration, and verification pass focused on the parts that are still weak after the previous backend/platform work.

This pass is NOT a cosmetic UI redesign.

The objective is to make NX AI feel and behave like a coherent, polished, practical desktop AI agent where:

- UI is properly managed and aligned.
- Data/state has one clear source of truth.
- Text never escapes its container.
- Notifications are useful, readable, deduplicated, and non-annoying.
- Panels, drawers, sidebars, sliders, and modals actually open/close and resize.
- Microphone access actually works on a supported interactive desktop session.
- Listening / thinking / speaking states are visible and understandable.
- Voice input can capture speech and convert it to usable commands.
- Voice output can speak responses.
- Barge-in/interruption is handled.
- Assistant can reliably read/listen to the user message and respond to the correct message.
- Conversation state is coherent.
- Skills are real executable capabilities, not just cards in a UI.
- Memory is useful and actually affects future behavior.
- Instructions/system rules are real and actually influence execution.
- Agent responses become more accurate, context-aware, concise, and action-oriented.
- API key validation and model verification actually work in a real environment when credentials are valid.
- Provider/model data flows correctly from backend to frontend.
- Frontend never invents, duplicates, or fabricates backend state.
- The agent performs actions and verifies them instead of merely saying it did them.
- All unavailable features are accurately reported instead of being presented as functional.
- Every important state is observable.
- Every important action has a clear success/failure state.
- The complete system is tested end-to-end.

ABSOLUTE RULE:
NO-EVIDENCE = NOT DONE.

Never mark a feature VERIFIED because:
- code exists,
- a button exists,
- a route exists,
- a component renders,
- a test mock passed,
- a static value appears,
- a UI card exists,
- the source code looks correct.

A feature is VERIFIED only after actual execution and evidence.

2. MASTER SOURCE-OF-TRUTH ARCHITECTURE
====================================================================================================================

The biggest frontend issue is likely fragmented state.

Create one coherent source of truth.

Backend owns:
- actual task state
- actual provider state
- actual model state
- actual memory state
- actual skill state
- actual worker state
- actual telemetry
- actual voice session state where applicable
- actual verification state

Frontend owns:
- presentation state
- local UI preferences
- currently open panel
- local form state
- temporary input state
- animation state

Frontend MUST NOT invent backend state.

Examples of invalid architecture:

- UI says task complete before backend verification.
- UI says provider healthy while backend says auth failed.
- UI says skill installed while tool is not executable.
- UI says memory saved while persistence failed.
- UI says microphone is listening while browser has no permission.
- UI says speaking while no audio is playing.
- UI shows model count from stale local state.
- UI duplicates events because multiple fetches update the same state.

Implement explicit state ownership.

Use stable IDs.

Avoid duplicate objects representing the same entity.
